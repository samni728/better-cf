# 产品设计

## 核心用户

核心用户是使用 Shadowrocket、OpenWrt、自建节点或类似代理 / 网络工具的个人运维用户。用户希望在当前 VPS 或本地网络环境中找到更快的 Cloudflare Anycast IPv4 / IPv6，并把同一轮优选结果同步到自己管理的一个或多个 DNS 目标。

典型用户不是要管理复杂 CDN 平台，而是要解决三个具体问题：

```text
我的网络环境下，哪些 Cloudflare IP 现在最快？
我怎样用一次扫描结果同步多个域名 / Zone？
我怎样确认每个 Cloudflare DNS 目标都同步成功？
```

## 核心痛点

当前 CLI 工具已经能跑出优选 IP，但存在几个问题：

- 需要手动执行，不方便追踪历史。
- 一次测速结果不能稳定、可观测地分发到多个 DNS 目标。
- 多账号 / 多 Zone 时，凭据与域名配置容易重复和混乱。
- 不知道写入 DNS 的 IP 是什么时候测出来的、用了多久、是否仍然稳定。
- 传统“先删旧记录再建新记录”的流程在创建失败时可能造成解析空窗。
- 如果脚本直接操作 DNS，缺少“只操作指定 Zone + 完整域名 + 记录类型”的安全边界和反查确认。

## 产品定位

本项目定位为：

```text
Cloudflare BetterIP DNS Sync
```

它不是泛用 DNS 管理器，也不是复杂代理面板。它只专注一件事：

```text
把当前网络测出的一份优选 Cloudflare IP，
安全、可追溯地 fan-out 到用户明确配置的 DNS 目标。
```

## MVP 第一条闭环

MVP 仍然只保留一个主用户、一个主场景和一个主数据流：

- 主用户：当前 VPS / 节点拥有者。
- 主场景：每天或手动扫描优选 Cloudflare IP，并同步到所有已启用 DNS 目标。
- 主数据流：测速参数 -> 一份扫描结果 -> 多目标 fan-out -> 逐目标 Cloudflare 反查 -> WebUI 汇总。
- 主交付结果：用户配置的每个完整域名都解析到最新一批经过测试的 A / AAAA，且页面可确认每个目标的结果。

多 DNS 目标不是多个业务流程；它们是同一扫描闭环的多个交付终点。

## Now / MVP

第一版必须做：

- 首次访问 WebUI 时创建单一管理员账号和密码。
- 管理员登录后才能访问凭据、DNS 目标、扫描、DNS 同步和历史记录。
- Cloudflare 凭据库：
  - 可新增、编辑和删除多组凭据。
  - 支持 API Token。
  - 支持 Email + Global API Key。
  - 凭据可被多个 DNS 目标引用。
  - 被引用的凭据不允许直接删除。
- DNS 目标列表：
  - 可新增、编辑、启用 / 停用和删除。
  - 字段包含名称、根域名、Zone ID、完整域名、`ipv4` / `ipv6` / `both`、凭据 ID。
  - 完整域名必须位于配置的根域名内。
- 旧版 single / split、统一 / 独立 Token 配置自动迁移到凭据库与 DNS 目标，迁移幂等，不重复创建项。
- WebUI 配置 IPv4 / IPv6、TLS / 非 TLS、目标结果数、带宽 Mbps、RTT 并发数和地区筛选。
- 每轮只扫描一次 IPv4 / IPv6，将同一份入选结果 fan-out 到所有已启用目标。
- 保存完整测速结果：设置 / 实测带宽、峰值速度、RTT、数据中心和总耗时。
- DNS 安全替换：
  - 只管理目标 Zone ID + 完整域名 + 记录类型精确匹配的集合。
  - 先创建缺失的新记录，创建全部成功后再删除过期记录。
  - 创建失败时不删除该目标的旧记录。
  - 写入后按目标反查 Cloudflare，确认实际集合与应写 IP 列表一致。
- Dashboard 和历史同时展示：
  - 入选优选 IP 数。
  - 已确认 DNS 目标数 / 计划目标数。
  - 已确认 DNS 记录数 / 应写记录数。
  - DNS 记录数按每个目标累计，不对相同 IP 去重。
- 每次执行保存扫描日志、逐目标 DNS 操作日志、错误与反查结果。
- 支持立即执行，以及每小时、每天固定时间、每 N 天固定时间执行。

管理员账号是单机部署 MVP 的安全边界。第一版不做多用户和权限矩阵，只保留一个管理员。

## Next

下一轮迭代：

- 当前 DNS IP 复测：从所有已管理目标收集 IP，去重后只测一次。
- 补位扫描：复测通过数量不足时，只扫描补足缺口。
- DNS 快照：更新前按 DNS 目标保存旧记录。
- 按单个 DNS 目标回滚到上一次快照。
- 更完整的历史运行详情页和 IP 历史页。
- 本地凭据静态加密或系统密钥链集成。

## Later

想法池：

- 多扫描配置 / 多定时任务，不同目标可选择不同扫描结果集。
- 多 VPS 对比测速。
- Shadowrocket 配置文件导出。
- OpenWrt API 自动下发。
- Telegram / 邮件通知。
- 历史速度趋势图。
- 更复杂的评分权重和稳定性策略。

## Risk

需要持续评估：

- Global API Key 权限过大：默认引导 API Token，所有密钥不回显、不记录日志。
- 多目标部分成功：必须按目标保留状态和错误，不用单个成功布尔值掩盖失败。
- 目标重叠管理：阻止两个已启用目标同时管理同一 Zone + 完整域名 + 记录类型。
- 配置迁移损坏旧数据：迁移必须幂等，且只在新凭据 / 目标列表为空时转换旧 single / split 字段。
- DNS 解析空窗：必须先创建缺失记录，全部成功后才删除过期记录。

## 产品原则

- 一次扫描、一份结果、多目标 fan-out。
- DNS 操作必须可解释、可追溯、可确认。
- 凭据和 DNS 目标解耦，凭据可替换，目标可独立启停。
- 默认使用最小权限 API Token，Global API Key 只作兼容选项。
- 删除操作必须严格限制到指定 Zone ID、完整域名和 A / AAAA 类型。
- 先创建、后删除；创建失败时保留旧记录。
- 所有敏感配置只在本地保存，不上传第三方，不出现在日志中。
- 第一版不做复杂多租户、权限矩阵和插件系统。

## Dashboard 体验原则

用户打开首页时，优先回答：

```text
现在是否正在执行？
执行到了哪一步？
今天入选了多少 IP？
本轮计划了多少 DNS 目标和记录？
已有多少目标、多少条 DNS 记录反查确认？
哪个目标需要处理？
日志在哪里？
```

信息优先级：

1. 当前状态：待配置、已就绪、正在执行、已同步、部分同步、需要处理。
2. 今日数据：入选 IP 数、已确认 DNS 记录数、任务次数、DNS 状态。
3. 当前进度：扫描阶段、fan-out 目标进度、已发现 / 已确认数量。
4. DNS 目标概览：完整域名、记录族、凭据名称、状态和确认数。
5. 最近任务：可展开查看实时和历史日志。
